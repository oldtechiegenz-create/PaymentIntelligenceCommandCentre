HARD CONSTRAINTS
----------------
1. Single file. All HTML, CSS and JavaScript inline.
2. Zero external dependencies: no CDNs, libraries, frameworks, web fonts,
   images, APIs, fetch/XHR, or build tools. Charts are hand-built inline SVG.
3. Opening the file in a browser (file://) must work immediately, and it must
   make zero network requests.
4. No real payment execution, no external banking APIs, no claim of sending
   SWIFT/Fed/TCH messages, no LLM calls. Kuber AI is a deterministic mock.
5. Do not auto-run a simulation on page load.
6. No console errors. JavaScript must pass `node --check` once extracted.
7. No localStorage/sessionStorage. All state lives in memory.
8. Use "use strict". Organize the code in several <script> blocks or one; shared
   top-level const/let bindings are fine because every call happens after
   DOMContentLoaded.

Factory mk(o) applies defaults: messageType pacs.008, USD/USD, fx 1, charges
SHAR, domain CBCC, status COMPLETED, intermediate SETTLED, statusReason "—",
screening CLEARED, settlementDate 2026-09-24, liquidity AVAILABLE, recon MATCHED,
aiRecommendation "No action required", purpose SUPP, addressFormat STRUCTURED,
settlementMethod INDA, priority NORM, riskScore 8, segment Corporate, aiAgent
Orchestrator, aiConfidence 0.9.
It also:
- fills bic from the debtor agent
- fills isoVersion from the message type: pacs.008.001.08, pacs.009.001.08,
  pacs.004.001.09, pain.001.001.09, pacs.002.001.10
- calls derive(p)

derive(p) recomputes (and clears the search-index cache):
- mtEquivalent: CBCC only — pacs.008→MT103, pacs.009→MT202,
  pacs.004→MT103 RETN, pain.001→MT101; otherwise "—".
- hops = the count of populated debtorAgent, correspondent, intermediary and
  creditorAgent.
- creditAmount = amount × fxRate.
- gpiStatus (CBCC only, else "—"): COMPLETED→ACCC; REJECTED/FAILED→RJCT/<code or
  NARR>; RETURNED→RTND/<code>; INVESTIGATION→ACSP/G003; simState or intermediate
  SETTLEMENT_PENDING→ACSP/G002; has a correspondent or intermediary→ACSP/G000;
  else ACSP/G001.
- exceptionType: REJECTED/RETURNED → BENEFICIARY_ACCOUNT when the reason code is
  AC03, else REJECTION; FAILED → NETWORK_SLA; INVESTIGATION → SCREENING_HOLD
  when screening contains MATCH or the reason mentions screen, else
  CORRESPONDENT_SLA; otherwise "—".
- slaState: COMPLETED→MET; IN_PROGRESS→AT_RISK when WAITING_CORRESPONDENT, else
  ON_TRACK; INVESTIGATION→AT_RISK; others→BREACHED.
reasonCode(reason) = the leading [A-Z0-9_]{3,} token (e.g. "AC03").

  • INVESTIGATION: "Potential sanctions match" when the description mentions an

FAILED, INVESTIGATION and CANCELLED map to themselves; every other state maps
to IN_PROGRESS.

- loadSimulationPayment(): does nothing while running. If the previous payment
  had a partial (paused, unfinished) run, restore its snapshot. Then clear the
  engine, set the new payment, re-render and show the suggestion. A finished

  set the steps and re-render.
- renderScenarioMeta(), renderStateMachine(), updateSimMetrics(),
  renderSimLog(), drawSeq(), renderRunHistory(), renderSimAll()
- startSimulation():
  • if already running, do nothing
  • if finished, run resetSimulation() first
  • on a fresh start: snapshot the payment (status, ultimateStatus,
    intermediateStatus, statusReason, screening, completedAt, duration,
    messageType, investigationId, reconState, aiRecommendation, aiAgent,
    events, simState), increment runSeq, set runId "SIM-20260925-NNNN", clear
    p.events and p._bl, then execute the first tick immediately (so the first
    event lands at 0.0s)
  • when resuming from a pause, schedule the next tick after the speed delay
  • set mode RUNNING and outcome RUNNING
- tickSimulation(): append steps[idx], increment idx, then finish or schedule
  the next tick.
- appendSimEvent(step, injected):
  • compute latency and build the event (ts = initiatedAt + cumulative latency,
    t = elapsed)
  • push it; increment iso when msg ≠ "—" and exc when the state is an
    exception state
  • set sim.state and call applySimState(p, ev)
  • build the payload and re-render the log, state machine, meta, metrics and
    sequence diagram, plus Payment 360 and evidence if this is the active
    payment, plus the grid
- applySimState(p, ev) — the simulator is authoritative:
  • simState = state; status = the derived payment status; intermediateStatus
    = state (SETTLED for COMPLETED)
  • ultimateStatus = the terminal state or IN_PROGRESS
  • statusReason set only for REJECTED/RETURNED/FAILED/INVESTIGATION, otherwise
    "—" (so AC03 appears on the reject path)
  • screening: "POTENTIAL MATCH" when the description contains "Potential",
    "CLEARED (human review)" when it contains "Human", "HOLD — POTENTIAL MATCH"
    on an analyst INVESTIGATION, otherwise CLEARED
  • completedAt only on COMPLETED; duration = the latency sum
  • messageType pacs.004 on RETURNED (and restored to the original non-return
    type at INITIATED)
  • investigationId generated ("INV-93000+runSeq") on INVESTIGATION if missing
  • reconState MATCHED / EXCEPTION / OPEN
  • aiRecommendation per state: "Monitor — within SLA"; "Route alert to
    screening analyst"; "Monitor — awaiting correspondent ACK"; "Escalate

    client"; "Analyst review of screening alert — human decision required" /

    incident; hold re-send pending camt.029"
  • aiAgent by state
  • p.events = sim.events; then derive(p) and refresh the option label
- pauseSimulation(): clear the timers, keep elapsed, mode and outcome PAUSED.
- resetSimulation(): restore the snapshot (the payment returns to its record
  state), clear the engine (READY, NO RUN, 0 ms, 0 ISO messages, 0 exceptions,
  no events, default payload, runId "—"), hide the banner and re-render
  everything.
- finishSimulation():
  • stop the timers, set finished and mode FINISHED
  • outcome = "FAILURE INJECTED" when injected, else the final state
  • show the banner, update metrics, state machine and meta
  • push the run history entry
  • post a Kuber system line: "Simulation SIM-… finished on ID: OUTCOME · N
    events · I ISO messages · E exceptions. Kuber observed the run; no external
    action was executed."
  • re-render Payment 360 and evidence
- injectFailure():
  • when not running: show "START SIMULATION FIRST" (banner and hint)
  • otherwise: stop the timer, set injected = true, append {FAILED, "Failure
    injected — processing aborted by chaos control", "pacs.002 RJCT"} (this

- buildIsoEvent(ev, p) → JSON with keys in THIS order:
  BusinessMessageId, UETR (null if none), PaymentId, MessageType (the msg base

  SimulatedLatencyMs, FailureInjected, ExternalActionExecuted:false,
  ReturnReason "AC03" on RETURNED, and TxSts (ACSP/ACCC/RJCT) when present in
